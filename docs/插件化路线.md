## 2. 架构与分层

```
GanttKnights/                     # 目录名 = metadata.yaml 的 name（实例里是指向它的联接）
├─ main.py                        # AstrBot 插件入口（导入期设 MPLCONFIGDIR + import matplotlib，§10）
├─ cli.py                         # CLI 入口（python cli.py）
├─ metadata.yaml  _conf_schema.json  requirements.txt  CHANGELOG.md  LICENSE
├─ prts_scraper.py                # 只爬活动数据并打印（调试用）
├─ src/                           # 渲染内核：纯 Python + matplotlib，**不认识 AstrBot**
│   ├─ 流水线.py                   # render_once()：数据 → 图片 + 警告（唯一渲染入口）
│   ├─ config.py                  # Settings（可注入路径 + GK_* 环境变量覆盖）
│   ├─ 字体.py                     # 字体三层候选 + 角色解析（注册字体唯一入口）
│   ├─ 绘图_*.py                   # 图表 / 主题 / 排版 / 颜色
│   ├─ 解析_*.py 汇总_活动.py 筛选_活动.py 活动.py 生成_警告.py
│   └─ 数据变化.py 数据保护.py 获取_prts.py
├─ 插件/                           # AstrBot 适配层（**只有这一层认识 AstrBot**）
│   ├─ 指令.py                     # CommandSpec：命令元数据单一来源 + 帮助文本
│   ├─ 配置.py                     # _conf_schema → 运行配置（读取处夹取越界值）
│   ├─ 文案.py                     # 用户可见文案常量
│   ├─ 渲染.py                     # 渲染服务：Agg + to_thread + 单飞锁（不留缓存）
│   └─ 推送.py                     # 每日推送：APScheduler + 目标读配置 + 幂等记账
├─ tests/                         # 零依赖契约测试（不 import AstrBot / matplotlib）
├─ docs/                          # 本文 + 配色规范
└─ 背景图/ 数据/ 字体/             # 本地资产（`数据/`、`字体/` 不进 git）
```

**分层规则（单向依赖）**：`main.py`（Star 子类：指令 + 生命周期）→ 构造注入 `插件/`
（指令 · 配置 · 文案 · 渲染 · 推送）→ 调用 `src/`（渲染内核）。

**骨架来源**：Star 子类 + 双参构造 + `CommandSpec` + 生命周期顺序参考 `astrbot_plugin_ark_calendar`
（致谢与许可声明在 README「许可与素材来源」）。参考物 `astrbot_plugin_palette` 的
Dashboard 注入 / `localStorage` / 内嵌 JS **一律不抄**，理由见 §7。

**关键不变式**：`src/**` 里**不允许 `import astrbot`**。CLI 因此永远可用，内核也能脱离 AstrBot 单测。
根 `__init__.py` 与 `插件/__init__.py` 都只放 docstring：宿主导入插件时会同步执行它们，
任何重依赖都不能出现在这里。

**入口发现规则**（`core/star/star_manager.py::_get_modules()`）：目录下先找 `main.py`，
找不到再找与目录同名的 `<目录名>.py`；**两者都在时永远用 `main.py`**，另一个被静默忽略。
目录名必须等于 `metadata.yaml` 的 `name`（安装期宿主会 `os.rename` 成它）。

**导入方式不可互换**：`cli.py` 以脚本方式运行（`__main__` 无父包）→ 只能绝对导入 `from src...`；
`main.py` 被宿主以 `data.plugins.<目录名>.main` 导入 → 只能相对导入 `from .src... / from .插件...`。

**入口形状**（真实代码见 `main.py`，这里只记必须守住的点）：

```python
PLUGIN_NAME = "astrbot_plugin_ganttknights"
插件版本 = "0.1.0"                    # 与 metadata.yaml / pyproject.toml 三处一致（测试钉住）

class GanttKnightsPlugin(Star):
    def __init__(self, context: Context, config: AstrBotConfig | None = None):
        super().__init__(context)     # config 不走 super()，自己存
        self.config = config if config is not None else {}   # 允许缺省：没有 schema 时宿主不传
        self.data_dir = Path(get_astrbot_data_path()) / "plugin_data" / (self.name or PLUGIN_NAME)
    async def initialize(self) -> None:   # 建目录、清旧版本残留、武装定时任务（不爬不渲染）
    async def terminate(self) -> None:    # 关停调度器（**绝不要给这个类加 __del__**，§3）
```

## 3. 宿主硬事实（照此实现，别再试）

**生命周期**：`import main.py`（**导入期**）→ 构造 `Star` 子类（`__init__`）→ `await initialize()`
→ 事件循环里调用指令 handler → 卸载时 `await terminate()`。之后插件对象一直驻留内存，
**每次使用不会重新导入模块、不会重跑 `initialize()`**。

- 只有**导入期**抛 `ModuleNotFoundError` 才能触发宿主的"自动装依赖"（§10）；`initialize()` 失败只会
  把插件标成"加载失败"。
- ⚠️ **不要给插件类加 `__del__`**：`star_manager.py:2022-2041` 是 `if __del__ … elif terminate`，
  加了之后 `terminate()` 永不执行 → 热重载后双实例双推送。

**配置**（`_conf_schema.json`）

- 只有存在 schema 时宿主才给 `__init__` 传 `config` → 声明为可缺省，别让加载期 `TypeError` 毙掉插件。
- **存储值永远优先于 schema 的默认值**：首次加载会把默认值写进用户配置文件，之后改 schema 默认值
  老用户**不会跟随** → 改默认值必须写进 `CHANGELOG.md`。
- `minimum` / `maximum` 只是文档，原生表单**不读**它们 → 后端在读取处自己夹取（`插件/配置.py`）。
- `template_schema` 的子项键名必须用 `name`（本插件用不到它）。
- 用户配置里的废弃键由宿主 `check_config_integrity` 自动剔除（只记日志，不报错）。

**数据目录**：官方写法是 `Path(get_astrbot_data_path()) / "plugin_data" / self.name`；
**不要**用内部 API `get_astrbot_plugin_data_path()`。
`AstrBotConfig.save_config()` 在 4.17 里没有（4.28 有）→ 调用处用
`callable(getattr(self.config, "save_config", None))` 守着。

**指令**

- **指令名不带前导斜杠**：`WakingStage` 先剥掉 wake_prefix（默认 `/`，`core/pipeline/stage.py:128`），
  `CommandFilter` 比较的是无斜杠原文 → `@filter.command("甘特图")`。斜杠只出现在给用户看的帮助里。
- `alias=` 必须传 **set**（`register_command(..., alias: set | None)`）；
  `CommandFilter.filter` 要求 `msg == cmd` 或 `msg.startswith(cmd + " ")` → 指令之间不会串味。
- 管理员权限：`@filter.permission_type(filter.PermissionType.ADMIN)`。
- 参数解析要自己做（框架按空白切分）；参考物按**命令名长度倒序**剥离前缀，避免短名吃掉长名。

**投递**

- 只用 `event.unified_msg_origin`：裸 `session_id` 会在 `message/message_session.py:26` 的
  `split(":", 2)` 处抛错（参考物为此真实翻过车）。
- `context.send_message(umo, MessageChain([...]))` 返回 **`False` 表示"未投递"**（不抛异常）→
  必须显式判，否则成功计数虚假；非法 umo 会直接 `ValueError`。
- `event.image_result(本地路径)` 内部转成 `file:///` URL → 测试里拿到的是 URL 不是路径。

**调度**（自建 `AsyncIOScheduler`；宿主的 `cron_manager` 在插件 `terminate()` **之前**就 shutdown 了，
见 `core/core_lifecycle.py:392-398`，且该 API 无文档）

- APScheduler 3.11 的 `misfire_grace_time` **库默认只有 1 秒** → 必须显式写（我们用 600）。
- `AsyncIOScheduler.start()` 必须在事件循环里调用（内部走 `asyncio.get_running_loop()`）且**不幂等**
  → 只能放 `initialize()` 或指令里；`shutdown()` 是 `call_soon_threadsafe` 投递，
  之后要 `await asyncio.sleep(0)`；`AsyncIOExecutor` 会 cancel 未完成协程 → 任务体要容忍 `CancelledError`。

**依赖**

- 宿主只在「从市场 / 仓库 URL 安装」「上传 zip 安装」「更新插件」「插件导入失败后修复」时跑插件的
  `requirements.txt`；**普通 `load()` 与 `reload()` 都不跑**。
- `requirements.txt` **只写裸依赖名**（锁版本会与宿主依赖打架）。
- 宿主自带 `httpx[socks] / pillow / apscheduler / aiohttp`（`importlib.metadata.requires("astrbot")` 实测），
  **不带 numpy / matplotlib** → 我们真正要自己装的只有这两个。

**市场身份**：`plugin_id = author/name`；市场记录的 `author` / `name` / `version` 必须与已安装包的
`metadata.yaml` **逐字一致**；`repo` 只能是 `https://github.com/{owner}/{repo}[.git|/tree/{branch}]`。

## 4. 踩坑清单

> 全文档最有价值的一张表：每条都是真实踩过或读源码确认过的。改代码前扫一眼。

| 坑 | 事实 | 我们的对策 |
|---|---|---|
| `requirements.txt` 锁版本 | 参考物锁 `aiohttp` 与宿主冲突，最后全部解锁 | **只写裸依赖名** |
| 数据目录 API | `get_astrbot_plugin_data_path()` 是内部名字；官方文档给的是 `get_astrbot_data_path()` + 手工拼 `plugin_data/<name>` | 走文档化写法 |
| 主动推送的会话 ID | `event.message_obj.session_id` 是**裸会话号**，`Context.send_message()` 无法解析，会让推送静默失败 | **只用 `event.unified_msg_origin`** |
| `send_message` 返回值 | 返回 `False` 表示**未投递**（不抛异常） | 显式判 `is False`，否则成功计数虚假 |
| `_conf_schema.json` 默认值 | 首次加载写入配置文件后，**存储值永远优先于 schema** → 以后改默认值老用户不会跟随 | 默认值变更必须写进 CHANGELOG |
| `template_schema` 子项键名 | 必须用 `name`；`title` 不被 AstrBot 读取 | 不用 `template_schema`（配置简单） |
| `minimum`/`maximum` | AstrBot 原生配置渲染器**不读**它们，只是文档 | 后端在读取处夹取（`插件/配置.py`） |
| 指令名不带斜杠 | `WakingStage` 先剥 wake_prefix（`core/pipeline/stage.py:128`）再进指令过滤 | `@filter.command("甘特图")`；斜杠只写给用户看 |
| `Star.__init__` 的 config 参数 | 只有存在 `_conf_schema.json` 时加载器才传 `config` | 入口把 `config` 声明为可缺省并回落默认值 |
| 本地图片结果的形态 | `event.image_result(本地路径)` 内部会转成 `file:///` URL | 要判文件是否存在，用 `渲染结果.图片路径` 或 `url2pathname` |
| `FT2Font.load_char()` 遇缺字形 | 字体里没有该字形时（如只剩 DejaVu 量中文）**直接段错误 0xC0000005**，catch 不住，宿主进程一起挂（matplotlib 3.11 实测） | 文本度量用 `TextToPath.get_text_width_height_descent()`（缺字形只 warning）；粗筛字形用 `get_char_index()` |
| `fontManager.addfont()` 不去重 | 同一支字体每 `addfont` 一次就往 `ttflist` 加一条并清 findfont 缓存（实测 ~96ms/次，长驻进程表会一直涨） | 注册只做一次（`src/字体.py::注册字体()` 是唯一入口 + 指纹缓存） |
| **长驻进程里的"一次性守卫"** | AstrBot 是长驻进程，"禁用插件→启用插件"**不会重载**已 import 的模块：`注册字体()` 原本用 `_方案 is None` 早退 → 用户出图后再往 `data/font.ttf` / `字体/` 放字体**永远不生效**（实测：同进程 `False`、独立进程 `True`） | 一切"只做一次"的缓存都要有**失效判据**：字体按 `字体指纹()`（字体目录 + 额外字体 + family/path 的 stat）失效 |
| **「现在时间」会驱动数据清理** | `src/汇总_活动.py::合并保存CSV` 用调用方传入的时间推导清理线 → 传入的时间偏新会把所有条目判过期、写回只剩表头，**且不报错**（真实事故：注入 `2026-09-13` 把 21 条清成 0 条） | 调试时**绝不给会写数据的路径注入未来/基准时间**（`render_once(强制刷新=False)` 不写数据，注入是安全的）；`src/数据保护.py` 兜底：已有非空→待写为空、或清理比例 >50% 且已有 ≥10 条 → **拒绝写盘并保留原文件**（需要大清理时显式传 `允许大幅清理=True`）。⚠️ 护栏只保活动 CSV，`新增预告.json` 与图标缓存没有 |
| **"已解析过"不等于"内容没变"** | 公告页会被**追加**（新的剿灭轮换写在当期活动的公告里）；旧代码"来源已在库里就整组跳过"→ 追加内容永远看不到（实测实例那份数据缺剿灭） | **别做这种增量跳过**：日常只扫"进行中 + 近 30 天结束过"的活动，看得到的事件**每次重读公告**；初始化扫全部。曾试过"页面修订时间台账 + 90 天复查窗口"来省请求，被自己删掉——状态比省下的请求贵 |
| 公告年份不能按"今天"猜 | 公告只写 `X月X日`，旧实现拿**今天**当基准 → 2025 年的老公告被算成未来（`揭幕者们2025` 变 2026-12），生成一批"未来活动"永久留在库里 | `src/解析_公告.py`：正则支持**可选年份**；没写年份时按**父活动时间窗中点**的最近年份（`_择年`）；结束早于开始时结束年 +1 |
| **增量抓取算不出"不再列出"** | "这次没抓到" ≠ "源里没了"：日常窗口本来就扫不到老活动，只有公告才有的条目（剿灭）会被误报成"不再列出" | 日差只保留能可靠推出的三项：`新增 / 时间调整 / 过期清理`；被撤下的活动让它自然过期 |
| **宿主不会自动装插件依赖** | 只在 market/URL/zip 安装、更新、**插件导入失败**时跑 `requirements.txt`；`load()` / `reload()` 不跑 | 导入期 `import matplotlib`（+176ms），让"缺依赖"变成"导入失败"（§10） |
| `MPLCONFIGDIR` 设晚了 | matplotlib 只在**首次导入**时读它；宿主进程里若已经有别的插件导入过 matplotlib，之后设也没用 | `main.py` 导入期**先设再 import**（§10）；`渲染服务.准备matplotlib环境()` 只作兜底，别指望它改路径 |
| 自定义字体槽放错字体 | 往 `data/font.ttf` 放一支纯拉丁字体不会报错，只会让整张图的中文变豆腐块 | 三层候选带**字形闸门**：`get_char_index('中')` 查不到就忽略并告警（**不要用 `load_char`**，见上一行） |
| 平台主动推送能力 | `platform.meta().support_proactive_message` 是 4.28 新增且**默认 True** | **不预检**：发一次并把结果记进推送状态，比读字段可靠（§9） |
| AI 工具 API | `astrbot.core.agent.tool` 是内部路径，且 AstrBot 自身有 reload 后插件工具失效的 issue | 不做 AI 工具；真要做时按官方文档的 `FunctionTool` 子类写法 |
| 内嵌 JS | 参考物把 1845 行 JS 塞进 Python f-string，双花括号破坏一切前端工具链 | 需要前端时走 `pages/` 静态资源，**绝不内嵌** |
| 查中文路径别用 `Select-String` 过滤 `git ls-files` | git 默认转义非 ASCII 路径（`core.quotepath`）→ 既匹配不到中文也匹配不到扩展名，得到**假阴性** | 用 `git -c core.quotepath=false ls-files` |
| 探针脚本别用 `tempfile.mkdtemp()` | Windows 上按 `mode=0o700` 建目录并写"只给创建者 SID"的 DACL；受限 SID 下连子目录都建不了（`WinError 5`） | 用 `仓库根/tmp/探针_<pid>_<时间戳>` + `mkdir(parents=True)`；`tests/conftest.py` 也覆盖了 pytest 的 `tmp_path` |

## 5. 仍然生效的关键决定

| 决定 | 一句话理由 |
|---|---|
| **不留渲染缓存** | 每天出一张图、请求低频；签名 + manifest + 失效那套（~380 行、8 类 bug）比省下的 1.4s 贵得多 |
| **日差由合并动作当场产出** | 抓完做合并的那一刻天然知道谁是新来的/谁被改了/谁过了清理线（`src/汇总_活动.py::合并差异` → `src/数据变化.py` 按天落盘）——不需要快照与事后对比 |
| **抓取策略：初始化全量 + 日常只扫最近的** | 初始化（CLI `--bootstrap` / `/甘特图初始化`，全新安装自动做一次）扫所有活动；日常只扫"进行中 ∪ 近 30 天内结束过"（`近期窗口天 = 30`），看得到的事件每次重读公告 |
| **字体不随包**，走三层候选 | 省掉 ~34MB；缺字体不再出豆腐块。三层见下 |
| **不用衬线字体** | 衬线只用在页眉大标题与底栏分区标签两处纯中文短串上，纯审美；而旧兜底在缺字体时会落到可变字体（ExtraLight），标题反而更细 |
| **背景按自然日确定性抽签** | `候选[crc32(日期) % 张数]`：同一天群里看到的图是同一张，不会因为谁先谁后而换配色；想指定就填 `render.background_file` |
| **配置只暴露 13 项** | 答不上来"用户什么时候会改它"的旋钮不暴露（字体、请求条数、`future_buffer_hours`、复用窗口、随机背景开关都被砍过） |
| **依赖按生态的约定俗成** | 导入期 `import matplotlib`（前面先设 `MPLCONFIGDIR`）→ 缺依赖时导入失败 → 宿主自动装并重试（§10） |
| **渲染在 `asyncio.to_thread` + 单飞锁 + Agg** | matplotlib 是同步 CPU 密集、`获取_prts` 是同步 httpx；`rcParams` 与 pyplot 是进程级全局，并发渲染会互相污染 |
| **进度文案只有一条**（`准备中`） | 入口层不做"会不会要等"的预判：复制一条会与真判定分叉的路径，只为少发一句话（实测分叉 4/40） |
| **素材问题用 `素材缺失` 异常一次说清** | 避免"预检"与锁内真检查重复；顺带修掉"`background_file` 写错会静默画出默认配色"的漏洞 |
| **三处单一来源**：`CommandSpec` / `插件/配置.py::字段映射` / `插件/文案.py` | 指令元数据、配置契约、用户文案各只有一份，测试钉住它们与 schema / README 一致 |

**字体三层候选**（`src/字体.py::注册字体()` 是唯一入口，结果按**字体来源指纹**缓存）

| 层 | 来源 | 说明 |
|---|---|---|
| ① 随包 | `字体/` 下的 4 个静态字重 | 设计基线；命中即"逐像素与历史一致"。仓库里**为空**是正常的 |
| ② 自定义 | AstrBot 约定槽 `data/font.ttf` / `font-bold.ttf` / `font-mono.ttf`（或 `font_path`+`font_family`） | 官方文档化的插槽；带**字形闸门**（`get_char_index('中')`） |
| ③ 平台 | Noto CJK → `Microsoft YaHei` → `PingFang SC` → `Hiragino Sans GB` → `Noto Sans SC` → `Droid Sans Fallback` → `AR PL UMing CN` | 缺 ①② 时兜底；Windows/macOS 上等宽角色落到雅黑/苹方，**它们的拉丁数字也是等宽数字**，日期轴不会乱 |

- `真粗体` 按"解析出的 bold 文件 ≠ regular 文件"判定（雅黑粗体、Noto CJK Bold 算真粗体；
  同文件的可变字体算没有 → 调用方转同色描边兜底）。
- 实测：换字体**版面 86/86 次文字绘制完全相同**（内容/坐标/字号/对齐），像素差只来自字形与抗锯齿；
  无 `字体/` 时落到雅黑 + 雅黑粗体，正常出图无豆腐块。
- 文本度量用**真实度量**（默认；`GK_文本度量=估算` 可退回）：默认 19 天窗口下与估算**逐像素零差异**
  （版面决定对 ±20% 宽度误差都不敏感），拉长窗口后条被压窄时才可能差 1 处"名字放条内还是条外"。
  代价冷缓存 +19ms / 热 ~0。
- 时间窗上限**30 天**（`right_offset_days`）：30 天时名字/日期判定余量还有 60px / 7px，
  35 天起贴边，≥45 天开始真的分歧。
- 已知边界：matplotlib 字体表**只增不减**，所以**删掉**字体文件后本进程内可能仍解析到旧路径
  （要重启才彻底收敛）。

## 7. 明确不做的事

1. **不注入/改写 AstrBot Dashboard 的 `index.html`**（无官方 API、版本耦合、卸载不干净）。
2. **不写宿主的 `localStorage` 主题键**。
3. **不把 JS 塞进 Python f-string**；要前端就走 `pages/` 静态资源。
4. **不锁依赖版本**（与是否上架无关，本地也会炸）。
5. **不把 `字体/`、`数据/` 提交进仓库**（体积 + 用户数据分离；`背景图/` 只 3MB，进仓库方便换机器）。
6. **不做 AI 工具**（内部 API 不稳，reload 有已知 issue）。
7. **不改 `src/` 下的中文模块名**（改动面大、收益低）。
8. **不为了插件砍掉 CLI**（单人调试时 CLI 比重启 AstrBot 快得多）。
9. **不做 `pages/` 设置页**、**不做字体子集化**（前者 `_conf_schema` 够用，后者已经不随包字体）。
10. **不做逐字回退混排与跨平台字体统一**（三层候选已够；实测换字体版面零位移）。
11. **不为上架做元数据以外的适配**：不加 i18n、不自建 logo、不声明未验证的平台。
12. **不做渲染缓存 / 预热 / 退避重试 / 多会话限流**（机器长期开机、单张 1.4s、请求低频）。
13. **不做开机补推 / misfire 补推**（同上：错过就静默跳过，宁可少推一张也不推过期图）。

## 9. 每日推送

目标只有一句：**每天把那张图发到用户常待的会话里**（`插件/推送.py`）。

| 部件 | 做法 |
|---|---|
| 目标会话 | 读配置 `push.targets`（list）：列表为空时把第一个发 `/甘特图` 的会话自动填进去，之后由用户在设置页增删（**删掉某一项 = 取消那个群的推送**）；状态文件只留记账 |
| 推送内容 | 图片 + **文字只在有话可说时才有**：日差（`🆕 新增 / ✏️ 时间调整 / 🧹 过期清理`）与真有事的提醒；都没有就只发图 |
| 定时 | 自建 `AsyncIOScheduler()`（跟随进程本地时区）+ `CronTrigger(hour, minute)` + 稳定 job id |
| job 参数 | `replace_existing=True`、`coalesce=True`、`max_instances=1`、**显式 `misfire_grace_time=600`** |
| 武装时机 | `initialize()` + **每次指令之后**都调一次 `确保任务()`（幂等：指纹 = 开关/该武装/时刻/会话数）→ WebUI 改完不必重启 |
| 推送动作 | 渲染**一次**（锁内）→ **锁外**循环投递 → 记账 |
| 幂等 | `已推 = {umo: 日期}`，**只记成功**；失败的会在下一次触发时重试 → 热重载双实例也只各推一次 |
| 卸载 | `terminate()` → `调度器.shutdown(wait=False)` + `await asyncio.sleep(0)` |

**为什么不做**：

| 没做 | 为什么 |
|---|---|
| 预热任务（提前渲染） | 只是把同一件事挪个时间，却要多一个 job、一段配置和一份状态 |
| 退避重试 | 数据文件 mtime 天然就是重试判据；投递失败记进状态、`/甘特图状态` 可见 |
| 平台能力预检 | `support_proactive_message` 默认 True 且是 4.28 新字段，信不过；发一次并把结果记下来更可靠 |
| 多会话限流 / 错峰 | 目标通常 1~2 个会话，顺序 `await` 就够 |
| `SQLAlchemyJobStore` | 停机错过的每日推送**就该静默跳过**，`MemoryJobStore` 正好是这个语义 |
| `/甘特图警告` | 每日推送已带警告文本，单独一条指令只是搬运 |

## 10. 缺依赖：宿主只在"插件导入失败"时替你装

**机制**（4.28 源码 + [PR #5954](https://github.com/AstrBotDevs/AstrBot/pull/5954)，2026-03-11 merged；
该 PR 的目标原文就是"解决插件安装/更新/上传流程中**依赖安装滞后于首次加载尝试**的问题"，并加了
核心依赖防降级约束）：

```
load() → _import_plugin_with_dependency_recovery()
   ├─ plan_missing_requirements_install(requirements.txt)   # 预检：只算缺的
   ├─ __import__(插件)                                       # 第一次导入
   └─ except ModuleNotFoundError:                            # ← 只认这一个类型
        ├─ 试"用已装的依赖恢复"（桌面版才有效）
        ├─ _check_plugin_dept_update() → pip install（用户配置的镜像 + 核心依赖约束）
        └─ __import__(插件) 再试一次 → 这次成功，用户什么都看不到
```

调用点：`install_plugin()` / `install_plugin_from_file()` / `update_plugin()` /
`reload_failed_plugin()` / `_import_plugin()` 的失败恢复分支。
**`load()` 与 `reload()` 不装**——所以"手动拷目录 + 重启"这种安装方式下，只有"导入失败"能救。

**我们的做法**：`main.py` 导入期先设 `MPLCONFIGDIR`、再 `import matplotlib`。

```python
_mplconfig = Path(get_astrbot_data_path()) / "plugin_data" / PLUGIN_NAME / "mplconfig"
_mplconfig.mkdir(parents=True, exist_ok=True)
os.environ["MPLCONFIGDIR"] = str(_mplconfig)     # ⚠️ 必须在首次导入之前（见 §4 同名列）
import matplotlib                                  # noqa: F401 —— 导入本身即"检查依赖"，别删
```

于是缺依赖 → 导入失败 → 宿主自动装 `requirements.txt` → 重试导入，**用户零操作**。
内核（`src/**`）仍然按需导入 pyplot 与绘图模块，CLI 与测试因此不背这个开销。
`tests/test_入口契约.py` 钉住这两行及它们的顺序。

**官方口径只有一句**（[插件开发指南](https://docs.astrbot.app/dev/star/plugin-new.html#插件依赖管理)）：
"务必在插件目录下创建 `requirements.txt`……以防止依赖未找到(Module Not Found)"。
[异常诊断](https://docs.astrbot.app/others/diagnostics.html) 把"依赖安装失败"列为插件异常常见类型，
只建议"检查插件依赖 / 看日志"。**没有任何官方文字讨论"重依赖要不要延迟导入"。**

**生态实测**（从市场挑 18 个"图像类 / 同类游戏数据类"插件，成功拉到 13 个的 `main.py` + `requirements.txt`）：

| 做法 | 数量 |
|---|---|
| **导入期就 import 重依赖**（因此天然落在官方自愈路径上） | **9** |
| 懒加载（函数体里 import） | 1 |
| 没有 `requirements.txt`（只用了宿主自带的库） | 3 |
| 做依赖自检 / 友好提示 | 0 |

**代价（实测，热缓存）**：`import matplotlib` 176ms（`matplotlib.pyplot` 352ms，仍留在渲染线程）；
插件入口导入 **138ms → 373ms**；对照 AstrBot 基座导入 ~2.5s。
取舍账：这一改动换掉了当时自建的 260 行依赖自检机制（§13）——**176ms 换 260 行，值**。
§5 的 pandas 优化（省 1.1s）不受影响。

**用户侧的兜底**（正常情况下用不到）：在插件页用「从仓库安装 / 上传 zip」重装一次（这条路径会顺带装
依赖；目录已存在就先删掉 `data/plugins/astrbot_plugin_ganttknights`，`data/plugin_data/` 的数据不受影响）；
或手动装进 **AstrBot 的解释器**：
`& "<AstrBot>\Scripts\python.exe" -m pip install -r "<插件目录>\requirements.txt"`，然后重载插件。

## 11. 判断规矩：新功能要不要加

新东西照这五条过一遍（都是从删掉的东西里总结出来的，清单见 §13）：

1. **不复制判定**：同一件事只判一次，判在离副作用最近的地方。"提前预判"只在能避免**昂贵**副作用
   （如一次 30s 网络抓取）时才值得，且结果必须**透传**给真判定。
2. **收益要能被用户感知**：省 0.26s 换 8.8MB 常驻、省一次写换两次读，都不算优化。
3. **配置项要能回答"用户什么时候会改它"**：答不上来就别暴露。
4. **常驻进程里一切"只做一次"的缓存都要有失效判据**（字体指纹就是为此而生）。
5. **先问"这个产品每天真正要回答什么"**：答案是"今天和昨天比变了什么"，
   于是缓存、预热、重试、限流都能被这一句否掉。

## 13. 试过并放弃的路线

> 只留结论，防止后人重走。每条都是**有理由**的放弃，不是"没做"。

| 放弃了什么 | 一句话理由 |
|---|---|
| 渲染签名缓存（`插件/缓存.py` ~380 行：签名 / manifest / 跨日失效 / 保留数 / 孤儿清理） | 每天一张图、请求低频；它带来的 8 类 bug（预判分叉、manifest 非对象、永久孤儿、路径越界、写失败毁图、发送竞态、跨日时区、删不掉文件）比省下的 1.4s 贵 |
| `render.reuse_seconds` 复用窗口 | 同上——"多久内复用旧图"这件事本身不该存在 |
| `render.random_background` 开关 | "指定背景文件"已覆盖；规则只保留"指定了就用它，否则按日抽签" |
| 内核 `lru_cache`（背景解码 / 配色推导） | 省 0.26s/次 换 8.8MB 常驻 + 指纹失效风险；实测删掉不改变任何像素 |
| 缓存命中前的"只读预判"（`查现成图()` / `更新计划()`） | 复制判定路径会与真判定分叉（实测 4/40），只为少发一句话 |
| `素材问题()` 预检 | 与锁内检查重复；改为 `素材缺失` 异常一次说清（顺带补上"背景文件名写错会静默出图"的漏洞） |
| `_同步一份()` 的"内容相同就跳过" | 要读 600KB 才能省 300KB 写——净亏 I/O |
| 让用户"抄 umo"填配置（参考物的 `push.target_sid_list`） | 让用户抄内部标识是设计缺陷；改成"第一个用指令的会话自动进配置、之后在设置页增删" |
| 预热任务 / 退避重试 / 平台能力预检 / 多会话限流 / `/甘特图警告` | 对 1~2 个会话、1.4s 渲染的量级没有可感收益（逐条理由见 §9） |
| 缓存 manifest 的路径容纳性校验 / 入缓存整图解码 | 随缓存一起删除；现在只保留发图前的廉价**魔数校验**（防"根本没画出来"） |
| 字体子集化（fontTools 裁剪 / `--retain-gids` / OFL 改名） | 不随包字体后完全不需要；且会引入"新增干员名缺字"的长期维护负担 |
| 随包完整 CJK 字库（4 个文件 ~34MB） | 三层候选已保证任何平台都出得了中文；要跨平台逐像素一致时再把文件放回 `字体/` |
| "系统字体不可行，必须随包字体" | 已被推翻：改成真实度量 + 去衬线 + 确认平台字体的拉丁数字本就是等宽数字 |
| 衬线字体 | 只影响两处纯中文短串，纯审美；缺字体时旧兜底还会落到可变字体（更细） |
| 参考物 palette 的 Dashboard 注入 / `localStorage` 主题键 / 内嵌 JS / `pages/` 设置页 | 见 §7：无官方 API、版本耦合、卸载不干净；`_conf_schema` 表单够用 |
| 自建依赖自检（`插件/依赖.py` 113 行 + 导入期关卡 + 149 行测试） | 用 176ms 启动换掉 260 行自建机制与一处"非约定俗成"写法；生态做法（导入期 import）就够了 |
| "顶层 `import numpy` 当绊线"（依赖自检的第一版） | 只覆盖被 import 的那一个依赖；"装了 numpy 却没装 matplotlib"会漏过去 |
| 公告页"修订时间台账 + 90 天复查窗口" | 状态比省下的请求贵；每天就一张图，简单优先 |
| 日差里的「不再列出」 | 抓取是增量的，"这次没抓到"推不出"源里没了"（会把剿灭误报成消失） |
| `已解析来源` 跳过整组 | 它屏蔽了"追加进老公告页的内容"（剿灭轮换就是这么丢的） |
| 每日"完整活动表快照 + 事后对比" | 合并动作本来就知道差异，快照是多余的中间状态 |
| 开机补推 / misfire 补推 | 机器长期开机；错过就静默跳过，宁可少推一张也不推过期图 |
| AI 工具（`astrbot.core.agent.tool`） | 内部 API 不稳，且宿主 reload 后有已知失效 issue |

## 14. 改动时看哪里

**最小维护清单**

| 你要改什么 | 必须一起动的地方 |
|---|---|
| 配置字段（加/删/改名） | `_conf_schema.json` + `插件/配置.py`（`字段映射` + 夹取范围）+ README「配置项」表 —— **三处同步**；`pytest` 的配置契约会核对（schema ↔ 代码默认值 ↔ 夹取范围 ↔ README 四处一致） |
| 配置默认值 | `CHANGELOG.md`（**存储值优先于 schema**，老用户不会自动跟随）+ 版本号 |
| 发版 | `metadata.yaml` 的 `version` + `main.py` 的 `插件版本` + `pyproject.toml` 的 `version`（**三处一致**，测试钉住）+ `CHANGELOG.md` 新增一节 + 到市场页面更新 |
| 改代码 | `python -m pytest tests -q` + `tmp/check_plugin.py`（期望 `未通过：无`）；动渲染再跑 `tmp/基准_渲染.py` |
| 改指令（名字/别名/权限/帮助） | 只改 `插件/指令.py` 的 `CommandSpec`（帮助文本与注册共用它，别手写第二份清单） |

| 改抓取窗口 / 初始化逻辑 | `src/解析_API活动.py`（`近期窗口天`）+ `插件/渲染.py::重建数据()` + `docs` 与 README 的说法；跑 `tmp/探_初始化流程.py` |
