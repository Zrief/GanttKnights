# GanttKnights 插件化：执行叙事

> 一件事：让「每天一张明日方舟活动甘特图」从命令行脚本变成**会在群里自己出现**的插件。
> 本文按**执行顺序**讲这条主线——每一步要解决什么问题、试过什么、最后定成什么；
> 每一步的结论就是今天代码里必须守住的约束。
> 纯查表用的材料放在后面：§7 宿主硬事实、§8 踩坑清单、§9 每日推送、§10 测试与验证、
> §11 明确不做 · 试过并放弃、§12 改动时看哪里。
> 引用优先用「小节标题」而不是编号（编号会随重排失效）。

## 1. 主线与产品判断

**产品判断**：这张图本身已经回答了"最近有什么活动"。插件唯一要做的是**在对的时间把图送到**。
这条判断后来否掉了一大堆"看起来专业"的东西（缓存、预热、退避重试、多会话限流 —— §11）。

```
PRTS Wiki ──抓取/解析──▶ 活动数据 CSV ──合并（产日差）──▶ 绘图内核 ──▶ Gantt.jpg ──▶ 群
                                            │                              ▲
                                            └── 提醒判定（节点）───────────┘
```

**现状**

| 项 | 值 |
|---|---|
| 上架 | **2026-09-15 已发布到 AstrBot 插件市场**；当前版本 **0.1.2** |
| 插件身份 | `plugin_id = Zrief/astrbot_plugin_ganttknights`；仓库 `https://github.com/Zrief/GanttKnights` |
| 环境 | AstrBot 4.28（作者机器 4.28.0、用户机器 4.28.1）/ Python 3.12.13；uv tool 装在 `~\AppData\Roaming\uv\tools\astrbot` |
| 代码 | 仓库根 `C:\acode\GanttKnights`；实例里以**目录联接**挂在 `data/plugins/astrbot_plugin_ganttknights` |
| 数据 | `data/plugin_data/astrbot_plugin_ganttknights/`：`所有活动数据.csv`、`新增预告.json`、`图片缓存/`、`警告.txt`、`最近数据变化.json`、`推送状态.json`、`Gantt.jpg`、`mplconfig/` |
| 素材 | `背景图/`（2 张、3.0MB，**进 git**）；`字体/`（**不进 git**，可以为空 → 走三层候选） |
| 分发体积 | **3.55MB**（市场 zip ≤16MB 的上限不构成约束） |
| 文档分工 | 本文（决策与活知识）+ [`docs/配色规范.md`](./配色规范.md)（版面与取色规范）+ `README.md`（面向用户） |

## 2. 起点：内核不许认识宿主

**问题**：已有的 601 行像素级排版是核心资产，不能为一个聊天平台重写；但内核一旦 `import astrbot`，
CLI 就废了，也没法脱离宿主单测。

**做法**

- 全部改成相对导入；路径通过 `src/config.py::Settings` 构造注入，`GK_*` 环境变量可覆盖。
- **关键不变式**：`src/**` 里**不允许 `import astrbot`**。CLI 因此永远可用。
- 根 `__init__.py` 与 `插件/__init__.py` 只放 docstring：宿主导入插件时会**同步执行**它们，
  任何重依赖都不能出现在这里。
- 顺手砍掉 `pandas`：它在本项目里只做纯 CRUD，却在导入期占 **1186ms**（实测）。
  换成 dataclass（`src/活动.py`）后整条 `src/流水线` 的导入 **1319ms → 297ms**。

**结论**：CLI 与插件共用 `src/流水线.py::render_once()` 一条渲染内核；固定背景下逐像素零差异。

```
GanttKnights/                     # 目录名 = metadata.yaml 的 name（实例里是指向它的联接）
├─ main.py                        # AstrBot 插件入口（导入期设 MPLCONFIGDIR + import matplotlib）
├─ cli.py                         # CLI 入口（python cli.py）
├─ metadata.yaml  _conf_schema.json  requirements.txt  CHANGELOG.md  LICENSE
├─ prts_scraper.py                # 只爬活动数据并打印（调试用）
├─ src/                           # 渲染内核：纯 Python + matplotlib，**不认识 AstrBot**
│   ├─ 流水线.py                   # render_once()：数据 → 图片 + 提醒（唯一渲染入口）
│   ├─ config.py                  # Settings（可注入路径 + GK_* 环境变量覆盖）
│   ├─ 字体.py                     # 字体三层候选 + 角色解析（注册字体唯一入口）
│   ├─ 绘图_*.py                   # 图表 / 主题 / 排版 / 颜色
│   ├─ 解析_*.py 汇总_活动.py 筛选_活动.py 活动.py 生成_提醒.py
│   └─ 数据变化.py 数据保护.py 获取_prts.py
├─ 插件/                           # AstrBot 适配层（**只有这一层认识 AstrBot**）
│   ├─ 指令.py                     # CommandSpec：命令元数据单一来源 + 帮助文本
│   ├─ 配置.py                     # _conf_schema → 运行配置（读取处夹取越界值）
│   ├─ 文案.py                     # 用户可见文案常量
│   ├─ 渲染.py                     # 渲染服务：Agg + to_thread + 单飞锁（不留缓存）
│   └─ 推送.py                     # 每日推送：APScheduler + 目标读配置 + 幂等记账
├─ tests/                         # 零依赖契约测试（不 import AstrBot / matplotlib）
├─ docs/                          # 本文 + 配色规范
└─ 背景图/ 数据/ 字体/             # 本地资产（`数据/`、`字体/` 不进 git）
```

## 3. 接上宿主：一层适配 + 三处单一来源

**问题**：宿主怎么发现插件、怎么传配置、指令元数据放哪、怎么不把宿主卡住。

**入口与发现**（`core/star/star_manager.py::_get_modules()`）

- 目录下先找 `main.py`，找不到再找与目录同名的 `<目录名>.py`；**两者都在时永远用 `main.py`**。
- 目录名必须等于 `metadata.yaml` 的 `name`（安装期宿主会 `os.rename` 成它）。
- **导入方式不可互换**：`cli.py` 以脚本方式运行（无父包）→ 只能绝对导入 `from src...`；
  `main.py` 被宿主以 `data.plugins.<目录名>.main` 导入 → 只能相对导入 `from .src... / from .插件...`。

**入口形状**（真实代码见 `main.py`，这里只记必须守住的点）

```python
PLUGIN_NAME = "astrbot_plugin_ganttknights"
插件版本 = "0.1.2"                    # 与 metadata.yaml / pyproject.toml 三处一致（测试钉住）

class GanttKnightsPlugin(Star):
    def __init__(self, context: Context, config: AstrBotConfig | None = None):
        super().__init__(context)     # config 不走 super()，自己存
        self.config = config if config is not None else {}   # 允许缺省：没有 schema 时宿主不传
        self.data_dir = Path(get_astrbot_data_path()) / "plugin_data" / (self.name or PLUGIN_NAME)
    async def initialize(self) -> None:   # 建目录、清旧版本残留、武装定时任务（不爬不渲染）
    async def terminate(self) -> None:    # 关停调度器（**绝不要给这个类加 __del__**，§7）
```

**配置**：只有存在 `_conf_schema.json` 时宿主才给 `__init__` 传 `config` → 声明为可缺省。
**存储值永远优先于 schema 的默认值** → 改默认值必须写进 `CHANGELOG.md`（老用户不会跟随）。
`minimum` / `maximum` 只是文档、原生表单不读 → 后端在读取处自己夹取（`插件/配置.py`）。

**三处单一来源**（各自只有一份定义，测试把三边钉在一起）

| 单一来源 | 管什么 |
|---|---|
| `插件/指令.py::CommandSpec` | 指令名 / 别名 / 权限 / 帮助文本（注册与帮助共用，别手写第二份清单） |
| `插件/配置.py::字段映射` | `(节, schema 键) → (代码字段, 取值方式)`；配置契约的唯一来源 |
| `插件/文案.py` | 用户可见文案常量 |

**指令**（`/甘特图警告` 有意不做：节点提醒已经跟着每日推送走了，单独一条指令只是搬运，§9）

| 指令 | 别名 | 权限 | 说明 |
|---|---|---|---|
| `/方舟日程` | `/方舟甘特` | 用户 | 出图；每次按当前数据渲染（不留缓存） |
| `/甘特图状态` | — | 用户 | 数据新鲜度 / 最近日差 / 推送情况 / 本会话 umo |
| `/甘特图刷新` | `/甘特图更新` | 管理员 | 强制重爬 + 重画 |
| `/甘特图初始化` | — | 管理员 | 全量回溯重建（全新安装会自动做一次） |
| `/甘特图帮助` | — | 用户 | 帮助 |

**别卡住宿主**（宿主是单事件循环）

- 渲染是同步 CPU、取数是同步 httpx → 全部塞进 `asyncio.to_thread`，外加**单飞锁**
  （`rcParams` 与 pyplot 是进程级全局，并发渲染会互相污染）。
- `matplotlib.use("Agg")` 必须在任何 pyplot 导入之前；`MPLCONFIGDIR` 必须在 matplotlib
  **首次导入之前**设好（容器/只读环境里默认配置目录不可写会报错或反复重建字体缓存）。
- **先说话、后出图**：handler 先 `yield` 一句"正在准备…"，再 `yield` 图片。
  进度文案**只有一条**：入口层不做"会不会要等"的预判——复制一条会与真判定分叉的路径，
  只为少发一句话（实测分叉 4/40）。
- 素材问题（背景图目录为空 / 指定的文件不存在）用 `素材缺失` 异常**一次说清**，
  不做"预检"与锁内真检查的重复；顺带修掉"`background_file` 写错会静默画出默认配色"的漏洞。

**字体与素材**（不随包，三层候选；`src/字体.py::注册字体()` 是唯一入口，结果按**来源指纹**缓存）

| 层 | 来源 | 说明 |
|---|---|---|
| ① 随包 | `字体/` 下的 4 个静态字重 | 设计基线；命中即"逐像素与历史一致"。仓库里**为空**是正常的 |
| ② 自定义 | AstrBot 约定槽 `data/font.ttf` / `font-bold.ttf` / `font-mono.ttf`（或 `font_path`+`font_family`） | 官方文档化的插槽；带**字形闸门**（`get_char_index('中')` 查不到就忽略并告警） |
| ③ 平台 | Noto CJK → `Microsoft YaHei` → `PingFang SC` → `Hiragino Sans GB` → `Noto Sans SC` → `Droid Sans Fallback` → `AR PL UMing CN` | 缺 ①② 时兜底；Windows/macOS 上等宽角色落到雅黑/苹方，**它们的拉丁数字也是等宽数字**，日期轴不会乱 |

已知边界：`right_offset_days` 上限 **30 天**（30 天时名字/日期判定余量还有 60px / 7px，35 天起贴边）；
matplotlib 字体表**只增不减**，所以**删掉**字体文件后本进程内可能仍解析到旧路径（要重启才彻底收敛）。

## 4. 两次自我推翻

### 4.1 第一次：把渲染缓存整个删掉

**问题**：同一天里重复请求，要不要复用上次画好的图？

**试过**：签名缓存（`插件/缓存.py` ~380 行：内容哈希签名 + manifest 原子写 + 跨日失效 +
保留数 + 孤儿清理 + 路径容纳性校验 + 入缓存整图解码）。一次对抗性审查在它里面抓到 **8 类 bug**
（预判分叉、manifest 非对象、永久孤儿、路径越界、写失败毁图、发送竞态、跨日时区、删不掉文件）。

**定案**：**删**。每天出一张图、请求低频；"少画一次"省下的 1.4s 不值这个复杂度。

- 顺带删掉内核里的 `lru_cache`（背景解码 / 配色推导）：省 0.26s 换 8.8MB 常驻 + 指纹失效风险，
  实测删掉不改变任何像素。
- `render.reuse_seconds`、`render.random_background` 一起退出配置面。
- **日差改由合并动作当场产出**：抓完做合并的那一刻天然知道谁是新来的、谁被改了、谁过了清理线
  （`src/汇总_活动.py::合并差异` → `src/数据变化.py` 按天落盘），不需要快照与事后对比。

### 4.2 第二次：提醒从"每天播报"改成"节点触发"

**问题**：推送的文案每天说什么？最早是"列出 3 天内即将结束的活动"，每天都列同一批。

**经过**：先精简（去掉首页上新、去掉两段式标题与结尾统计）→ 再干脆换成**节点判定**：

- 判据是 `偏移 =（今天 - 边界日).days` 命中配置里的数组（`notify.end_offsets` 默认 `[-3,-1]`、
  `notify.start_offsets` 默认 `[0]`），**无状态**：只看今天 + 数据 + 配置。
- 于是同一天渲染多少次都是同一份文案、跨天自然只响一次，**不需要台账**；停机几天错过的节点不补报。
- 文案：组头由偏移生成（`⚠️ 明天结束` / `3 天后结束` / `🔥 今天开启`），组内一事件一行
  （图标 + 名称），一次最多 **10 行**、超出补 `…另有 N 项`；**没命中就只发图**。
- 三层开关：总开关 / 结束侧 / 开始侧；数组留空同样静音。
- **推送分两条发**（先文字再图）：不少平台会把"图 + 文"合成一条带配文的图，图片被压小、文字被折叠。
- 日差从此**不进推送**（仍然算、仍然落盘、`/甘特图状态` 看得到日期、`/甘特图初始化` 会回显）。

## 5. 让数据准：初始化一次 + 日常只扫最近的

**问题一：剿灭、保全这类长期任务"检测不出来"。** 原因不是抓不到，而是两道门：

1. 日常增量会跳过"已结束"的活动，而剿灭轮换**写在当期活动的公告页里**；
2. 旧代码"来源已在库里就整组跳过"——公告页会被**追加**，追加内容永远看不到。

**定案**（用户给的那句话就够了："只要初始化了，就能动态维护下去了，只用扫最近的就可以了"）：

- 初始化（CLI `--bootstrap` / `/甘特图初始化`，**全新安装自动做一次**）扫**所有**活动的公告；
- 日常只扫"进行中 ∪ 近 30 天内结束过"（`src/解析_API活动.py::近期窗口天 = 30`）；
- 看得到的事件**每次都重读公告**，不看"解析过没有"、不记修订时间；
- 中途试过的"修订时间台账 + 90 天复查窗口"被删掉——状态比省下的请求贵。

**问题二：公告年份按"今天"猜。** 公告只写 `X月X日`，旧实现拿今天当基准 →
2025 年的老公告被算成未来（`揭幕者们2025` 变 2026-12），'生成一批"未来活动"永久留在库里'。

**定案**（`src/解析_公告.py`）：正则支持**可选年份**；没写年份时按**父活动时间窗中点**的最近年份
（`_择年`）；结束早于开始时结束年 +1。

**问题三：日差算不出"不再列出"。** "这次没抓到" ≠ "源里没了"——日常窗口本来就扫不到老活动，
只有公告才有的条目（剿灭）会被误报成"消失"。**定案**：日差只保留能可靠推出的三项
（`新增 / 时间调整 / 过期清理`），被撤下的活动让它自然过期。

**护栏**：`src/汇总_活动.py::合并保存CSV` 用调用方传入的时间推导清理线 → 传入的时间偏新会把所有条目
判过期、写回只剩表头，**且不报错**（真实事故：注入 `2026-09-13` 把 21 条清成 0 条）。
`src/数据保护.py` 兜底：已有非空 → 待写为空、或清理比例 >50% 且已有 ≥10 条 → **拒绝写盘并保留原文件**。
⚠️ 护栏只保活动 CSV，`新增预告.json` 与图标缓存没有；调试时**绝不给会写数据的路径注入未来时间**。

## 6. 装得上、上得了架

### 6.1 依赖：宿主只在"插件导入失败"时替你装

宿主只在「市场 / 仓库 URL 安装」「上传 zip 安装」「更新插件」「插件导入失败后修复」时跑插件的
`requirements.txt`；**普通 `load()` 与 `reload()` 都不跑**。而恢复分支只认 `ModuleNotFoundError`：

```
load() → _import_plugin_with_dependency_recovery()
   ├─ plan_missing_requirements_install(requirements.txt)   # 预检：只算缺的
   ├─ __import__(插件)                                       # 第一次导入
   └─ except ModuleNotFoundError:                            # ← 只认这一个类型
        ├─ 试"用已装的依赖恢复"（桌面版才有效）
        ├─ _check_plugin_dept_update() → pip install（用户配置的镜像 + 核心依赖约束）
        └─ __import__(插件) 再试一次 → 这次成功，用户什么都看不到
```

**定案**：`main.py` 导入期先设 `MPLCONFIGDIR`、再 `import matplotlib`（导入本身就是"检查依赖"）：

```python
_mplconfig = Path(get_astrbot_data_path()) / "plugin_data" / PLUGIN_NAME / "mplconfig"
_mplconfig.mkdir(parents=True, exist_ok=True)
os.environ["MPLCONFIGDIR"] = str(_mplconfig)     # ⚠️ 必须在首次导入之前
import matplotlib                                  # noqa: F401 —— 别删
```

- 缺依赖 → 导入失败 → 宿主自动装 `requirements.txt` 并重试，**用户零操作**。
- 内核（`src/**`）仍然按需导入 pyplot 与绘图模块：CLI 与测试因此不背这个开销。
- 代价（实测，热缓存）：`import matplotlib` 176ms，插件入口导入 **138ms → 373ms**；
  对照 AstrBot 基座导入 ~2.5s。§2 的 pandas 优化（省 1.1s）不受影响。
- `requirements.txt` **只写裸依赖名**（锁版本会与宿主依赖打架）；宿主自带
  `httpx[socks] / pillow / apscheduler / aiohttp`（实测），**不带 numpy / matplotlib**。

> 曾试过两版自建机制（顶层 `import numpy` 当绊线、`find_spec` 自检 + 主动抛），
> 最后都用 176ms 换掉了那 260 行——见 §11。

### 6.2 上架：市场元数据与身份

| README | 官方**没有**结构要求；唯一有规范依据的是"借鉴了别人的项目要写明并附链接、保留许可声明" | ✅ README「许可与素材来源」 |

- **`support_platforms` 只写 `qq_official` + `aiocqhttp`**：这个字段只进 `StarMetadata`、
  只透传给前端、只渲染成卡片上的平台 chip，**不参与安装 / 加载 / 指令过滤** → 只写站得住的。
  **不写有硬限制的**：`line`（图片必须能解析成公网 https URL）、`weixin_official_account`
  （客服消息只有 48 小时窗口）。⚠️ 实测差异：`qq_official` 的**群聊定时推送**需要群内开启
  「机器人主动在群聊内发言」（走主动消息接口），否则平台回 `主动消息失败, 无权限`——命令出图不受影响。
- **`astrbot_version: ">=4.17.0"`**：这个字段会**真的拦加载**，下限逐个核对过 v4.17.0 源码
  （`send_message(umo, chain)` / `filter.permission_type` / `register_command(alias=set)` /
  `get_astrbot_data_path()` / `astrbot.api` 导出 `AstrBotConfig` / `DEFAULT_VALUE_MAP` 含 `"list"` 都在）。
- **`tags` 8 个、中英各一份**：市场检索按标签字面匹配。只给"游戏名 + 产物类型"配英文。
- 没写：`social_link`、`logo`、`i18n`（见 §11）；`category` 由市场侧决定（若让选，选 `entertainment`）。
- **`CHANGELOG.md` 不是可选文档**：WebUI 插件页的「更新日志」按钮读的就是它。

## 7. 宿主硬事实（照此实现，别再试）

**生命周期**：`import main.py`（**导入期**）→ 构造 `Star` 子类（`__init__`）→ `await initialize()`
→ 事件循环里调用指令 handler → 卸载时 `await terminate()`。之后插件对象一直驻留内存，
**每次使用不会重新导入模块、不会重跑 `initialize()`**。

- 只有**导入期**抛 `ModuleNotFoundError` 才能触发宿主的"自动装依赖"（§6）；`initialize()` 失败只会
  把插件标成"加载失败"。
- ⚠️ **不要给插件类加 `__del__`**：`star_manager.py:2022-2041` 是 `if __del__ … elif terminate`，
  加了之后 `terminate()` 永不执行 → 热重载后双实例双推送。

**数据目录**：官方写法是 `Path(get_astrbot_data_path()) / "plugin_data" / self.name`；
**不要**用内部 API `get_astrbot_plugin_data_path()`。`AstrBotConfig.save_config()` 在 4.17 里没有
（4.28 有）→ 调用处用 `callable(getattr(self.config, "save_config", None))` 守着。

**指令**

- **指令名不带前导斜杠**：`WakingStage` 先剥掉 wake_prefix（默认 `/`，`core/pipeline/stage.py:128`），
  `CommandFilter` 比较的是无斜杠原文。斜杠只出现在给用户看的帮助里。
- `alias=` 必须传 **set**；`CommandFilter.filter` 要求 `msg == cmd` 或 `msg.startswith(cmd + " ")`
  → 指令之间不会串味（`/甘特图状态` 不会命中 `/甘特图`）。
- 管理员权限：`@filter.permission_type(filter.PermissionType.ADMIN)`。
- 参数解析要自己做（框架按空白切分）；参考项目按**命令名长度倒序**剥离前缀，避免短名吃掉长名。

**投递**

- 只用 `event.unified_msg_origin`：裸 `session_id` 会在 `message/message_session.py:26` 的
  `split(":", 2)` 处抛错（参考项目记录过这个坑）。
- `context.send_message(umo, MessageChain([...]))` 返回 **`False` 表示"未投递"**（不抛异常）→
  必须显式判，否则成功计数虚假；非法 umo 会直接 `ValueError`。
- `event.image_result(本地路径)` 内部转成 `file:///` URL → 测试里拿到的是 URL 不是路径。

**调度**（自建 `AsyncIOScheduler`；宿主的 `cron_manager` 在插件 `terminate()` **之前**就 shutdown 了，
见 `core/core_lifecycle.py:392-398`，且该 API 无文档）

- APScheduler 3.11 的 `misfire_grace_time` **库默认只有 1 秒** → 必须显式写（我们用 600）。
- `AsyncIOScheduler.start()` 必须在事件循环里调用且**不幂等** → 只能放 `initialize()` 或指令里；
  `shutdown()` 是 `call_soon_threadsafe` 投递，之后要 `await asyncio.sleep(0)`；
  `AsyncIOExecutor` 会 cancel 未完成协程 → 任务体要容忍 `CancelledError`。

**市场身份**：`plugin_id = author/name`；市场记录的 `author` / `name` / `version` 必须与已安装包的
`metadata.yaml` **逐字一致**；`repo` 只能是 `https://github.com/{owner}/{repo}[.git|/tree/{branch}]`。

## 8. 踩坑清单

> 每条都是真实踩过或读源码确认过的。改代码前扫一眼。

| 坑 | 事实 | 我们的对策 |
|---|---|---|
| `requirements.txt` 锁版本 | 参考项目锁 `aiohttp` 与宿主依赖冲突，最后全部解锁 | **只写裸依赖名** |
| 数据目录 API | `get_astrbot_plugin_data_path()` 是内部名字；官方文档给的是 `get_astrbot_data_path()` + 手工拼 `plugin_data/<name>` | 走文档化写法 |
| 主动推送的会话 ID | `event.message_obj.session_id` 是**裸会话号**，`Context.send_message()` 无法解析，会让推送静默失败 | **只用 `event.unified_msg_origin`** |
| `send_message` 返回值 | 返回 `False` 表示**未投递**（不抛异常） | 显式判 `is False`，否则成功计数虚假 |
| `_conf_schema.json` 默认值 | 首次加载写入配置文件后，**存储值永远优先于 schema** → 以后改默认值老用户不会跟随 | 默认值变更必须写进 CHANGELOG |
| `minimum`/`maximum` | AstrBot 原生配置渲染器**不读**它们，只是文档 | 后端在读取处夹取（`插件/配置.py`） |
| 指令名不带斜杠 | `WakingStage` 先剥 wake_prefix（`core/pipeline/stage.py:128`）再进指令过滤 | `@filter.command("方舟日程")`；斜杠只写给用户看 |
| `Star.__init__` 的 config 参数 | 只有存在 `_conf_schema.json` 时加载器才传 `config` | 入口把 `config` 声明为可缺省并回落默认值 |
| 本地图片结果的形态 | `event.image_result(本地路径)` 内部会转成 `file:///` URL | 要判文件是否存在，用 `渲染结果.图片路径` 或 `url2pathname` |
| `FT2Font.load_char()` 遇缺字形 | 字体里没有该字形时（如只剩 DejaVu 量中文）**直接段错误 0xC0000005**，catch 不住，宿主进程一起挂（matplotlib 3.11 实测） | 文本度量用 `TextToPath.get_text_width_height_descent()`（缺字形只 warning）；粗筛字形用 `get_char_index()` |
| `fontManager.addfont()` 不去重 | 同一支字体每 `addfont` 一次就往 `ttflist` 加一条并清 findfont 缓存（实测 ~96ms/次，长驻进程表会一直涨） | 注册只做一次（`src/字体.py::注册字体()` 是唯一入口 + 指纹缓存） |
| **长驻进程里的"一次性守卫"** | AstrBot 是长驻进程，"禁用插件→启用插件"**不会重载**已 import 的模块：`注册字体()` 原本用 `_方案 is None` 早退 → 用户出图后再往 `data/font.ttf` / `字体/` 放字体**永远不生效**（实测：同进程 `False`、独立进程 `True`） | 一切"只做一次"的缓存都要有**失效判据**：字体按 `字体指纹()`（字体目录 + 额外字体 + family/path 的 stat）失效 |
| **「现在时间」会驱动数据清理** | `src/汇总_活动.py::合并保存CSV` 用调用方传入的时间推导清理线 → 传入的时间偏新会把所有条目判过期、写回只剩表头，**且不报错**（真实事故：注入 `2026-09-13` 把 21 条清成 0 条） | 调试时**绝不给会写数据的路径注入未来/基准时间**；`src/数据保护.py` 兜底（拒绝写盘并保留原文件）。⚠️ 护栏只保活动 CSV |
| **"已解析过"不等于"内容没变"** | 公告页会被**追加**（新的剿灭轮换写在当期活动的公告里）；旧代码"来源已在库里就整组跳过"→ 追加内容永远看不到（实测实例那份数据缺剿灭） | **别做这种增量跳过**：日常只扫"进行中 + 近 30 天结束过"的活动，看得到的事件**每次重读公告**；初始化扫全部 |
| 公告年份不能按"今天"猜 | 公告只写 `X月X日`，旧实现拿**今天**当基准 → 2025 年的老公告被算成未来（`揭幕者们2025` 变 2026-12） | `src/解析_公告.py`：正则支持**可选年份**；没写年份时按**父活动时间窗中点**的最近年份（`_择年`）；结束早于开始时结束年 +1 |
| **增量抓取算不出"不再列出"** | "这次没抓到" ≠ "源里没了"：日常窗口本来就扫不到老活动，只有公告才有的条目（剿灭）会被误报成"不再列出" | 日差只保留能可靠推出的三项：`新增 / 时间调整 / 过期清理` |
| **宿主不会自动装插件依赖** | 只在 market/URL/zip 安装、更新、**插件导入失败**时跑 `requirements.txt`；`load()` / `reload()` 不跑 | 导入期 `import matplotlib`（+176ms），让"缺依赖"变成"导入失败"（§6） |
| `MPLCONFIGDIR` 设晚了 | matplotlib 只在**首次导入**时读它；宿主进程里若已经有别的插件导入过 matplotlib，之后设也没用 | `main.py` 导入期**先设再 import**；`渲染服务.准备matplotlib环境()` 只作兜底 |
| 自定义字体槽放错字体 | 往 `data/font.ttf` 放一支纯拉丁字体不会报错，只会让整张图的中文变豆腐块 | 三层候选带**字形闸门**（**不要用 `load_char`**，见上一行） |
| 平台主动推送能力 | `platform.meta().support_proactive_message` 是 4.28 新增且**默认 True** | **不预检**：发一次并把结果记进推送状态，比读字段可靠（§9） |
| **QQ 官方群聊的「主动消息」是另一套权限** | `qq_official` 的 `send_by_session` 对群聊**一律走主动消息**（`_allow_group_proactive_send = True`，payload 不带 `msg_id`）；平台会回 `主动消息失败, 无权限` | 在**手机 QQ 群设置 → 机器人**里开启「机器人主动在群聊内发言」；群主不是你时，把推送目标换到 OneBot（aiocqhttp）。失败会记进 `推送状态.json`、**下一次到点自动重试** |
| AI 工具 API | `astrbot.core.agent.tool` 是内部路径，且 AstrBot 自身有 reload 后插件工具失效的 issue | 不做 AI 工具；真要做时按官方文档的 `FunctionTool` 子类写法 |
| 内嵌 JS | 参考项目把 1845 行 JS 内嵌在 Python f-string 里，双花括号破坏一切前端工具链 | 需要前端时走 `pages/` 静态资源，**绝不内嵌** |

## 9. 每日推送

目标只有一句：**每天把那张图发到用户常待的会话里**（`插件/推送.py`）。

| 部件 | 做法 |
|---|---|
| 目标会话 | 读配置 `push.targets`（list）：列表为空时把第一个发 `/方舟日程` 的会话自动填进去，之后由用户在设置页增删（**删掉某一项 = 取消那个群的推送**）；状态文件只留记账 |
| 推送内容 | 图片；文字只在**命中节点**时才有（§4.2），且**分两条发**（先文字再图） |
| 定时 | 自建 `AsyncIOScheduler()`（跟随进程本地时区）+ `CronTrigger(hour, minute)` + 稳定 job id |
| job 参数 | `replace_existing=True`、`coalesce=True`、`max_instances=1`、**显式 `misfire_grace_time=600`** |
| 武装时机 | `initialize()` + **每次指令之后**都调一次 `确保任务()`（幂等：指纹 = 开关/该武装/时刻/会话数）→ WebUI 改完不必重启 |
| 推送动作 | 渲染**一次**（锁内）→ **锁外**循环投递 → 记账 |
| 幂等 | `已推 = {umo: 日期}`，**只记成功**；失败的会在下一次触发时重试 → 热重载双实例也只各推一次 |
| 卸载 | `terminate()` → `调度器.shutdown(wait=False)` + `await asyncio.sleep(0)` |

**为什么不做**：预热任务（只是把同一件事挪个时间）、退避重试（数据文件 mtime 天然就是重试判据）、
平台能力预检（字段信不过，发一次更可靠）、多会话限流（目标通常 1~2 个）、`SQLAlchemyJobStore`
（停机错过就该静默跳过，`MemoryJobStore` 正好是这个语义）。

## 11. 明确不做 · 试过并放弃

**明确不做**（现在的取舍）

1. **不注入/改写 AstrBot Dashboard 的 `index.html`**（无官方 API、版本耦合、卸载不干净）。
2. **不写宿主的 `localStorage` 主题键**；**不把 JS 塞进 Python f-string**（要前端就走 `pages/` 静态资源）。
3. **不锁依赖版本**（与是否上架无关，本地也会炸）。
4. **不把 `字体/`、`数据/` 提交进仓库**（体积 + 用户数据分离；`背景图/` 只 3MB，进仓库方便换机器）。
5. **不做 AI 工具**（内部 API 不稳，reload 有已知 issue）；**不改 `src/` 下的中文模块名**。
6. **不为了插件砍掉 CLI**（单人调试时 CLI 比重启 AstrBot 快得多）。
7. **不做 `pages/` 设置页**、**不做字体子集化**、**不做逐字回退混排与跨平台字体统一**
   （`_conf_schema` 够用；不随包字体后子集化没有意义；三层候选已够）。
8. **不为上架做元数据以外的适配**：不加 i18n、不自建 logo、不声明未验证的平台。
9. **不做渲染缓存 / 预热 / 退避重试 / 多会话限流 / 开机补推**（§1 的产品判断直接否掉；
   错过就静默跳过，宁可少推一张也不推过期图）。

**试过并放弃的路线**（只留结论，防止后人重走；每条都是**有理由**的放弃，不是"没做"）

| 放弃了什么 | 一句话理由 |
|---|---|
| 渲染签名缓存（`插件/缓存.py` ~380 行）与它的 `reuse_seconds` / manifest 路径校验 / 入缓存整图解码 | 每天一张图、请求低频；8 类真实 bug 比省下的 1.4s 贵（§4.1） |
| 内核 `lru_cache`（背景解码 / 配色推导） | 省 0.26s/次 换 8.8MB 常驻 + 指纹失效风险；实测删掉不改变任何像素 |
| 缓存命中前的"只读预判"、`素材问题()` 预检、`_同步一份()` 的"内容相同就跳过" | 复制判定会与真判定分叉（实测 4/40）；要读 600KB 才能省 300KB 写——净亏 I/O |
| `render.random_background` 开关 | "指定背景文件"已覆盖；规则只保留"指定了就用它，否则按日抽签" |
| 让用户手填会话标识（参考项目的 `push.target_sid_list`） | 让用户去复制内部标识是设计缺陷；改成"第一个用指令的会话自动进配置、之后在设置页增删" |
| 每日"完整活动表快照 + 事后对比"、日差里的「不再列出」 | 合并动作本来就知道差异；"这次没抓到"推不出"源里没了"（§5） |
| `已解析来源` 跳过整组、公告页"修订时间台账 + 90 天复查窗口" | 前者屏蔽了追加内容（剿灭轮换），后者状态比省下的请求贵（§5） |
| 自建依赖自检（`插件/依赖.py` 113 行 + 导入期关卡 + 149 行测试）、"顶层 `import numpy` 当绊线" | 176ms 启动换掉 260 行自建机制与一处"非约定俗成"写法；绊线只覆盖被 import 的那一个依赖（§6） |

**判断规矩**（新功能照这五条过一遍）

1. **不复制判定**：同一件事只判一次，判在离副作用最近的地方。"提前预判"只在能避免**昂贵**副作用
   （如一次 30s 网络抓取）时才值得，且结果必须**透传**给真判定。
2. **收益要能被用户感知**：省 0.26s 换 8.8MB 常驻、省一次写换两次读，都不算优化。
3. **配置项要能回答"用户什么时候会改它"**：答不上来就别暴露。
4. **常驻进程里一切"只做一次"的缓存都要有失效判据**（字体指纹就是为此而生）。
5. **先问"这个产品每天真正要回答什么"**：答案是"今天有什么节点要说"（§1），
   于是缓存、预热、重试、限流都能被这一句否掉。

**参考与调研来源**：读过哪些项目、各自起了什么作用（含 GitHub 链接），完整清单在
[README 的「致谢」](../README.md#致谢)一节——19 个仓库 + 官方市场全量 1332 条记录的统计。
本文件只记被借鉴的**结论**：骨架来自 `astrbot_plugin_ark_calendar`、「配置即契约」的测试思路来自
`astrbot_plugin_palette`、配色取色的实现对来自 `MaaAssistantArknights`、
